# 힙 정렬, 퀵 정렬 및 병합 정렬 성능 비교·분석 (Assignment 14)

본 프로젝트는 C언어를 기반으로 **힙 정렬(Heap Sort)**, **병합 정렬(Merge Sort)**, 그리고 **퀵 정렬(Quick Sort - 3가지 피벗 선택 방식)**의 성능을 측정하고 비교·분석하기 위한 프로그램입니다.

---

## 1. 실험 환경 및 데이터 생성
- **데이터 크기 ($n$):** 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
- **데이터 특성:** 0 ~ 999,999 범위의 무작위 정수 생성 (중복 값 허용, 오름차순 정렬 수행)
- **공정성 보장:** 각 데이터 크기별로 동일한 원본 난수 배열을 생성한 후, 각 알고리즘이 동일한 복사본(work array)을 사용하여 정렬을 수행합니다.

---

## 2. 정렬 알고리즘 구현 방식
1. **힙 정렬 (Heap Sort)**
   - 입력 배열 자체를 이용하여 최대 힙(Max Heap)을 구성합니다.
   - 루트의 최댓값을 힙의 마지막 원소와 교환한 뒤 힙 크기를 줄이고, `max_heapify`를 통해 힙 속성을 복구하는 과정을 반복합니다.
2. **병합 정렬 (Merge Sort)**
   - 분할 정복(Divide and Conquer) 방식을 사용하여 배열을 반으로 나눈 뒤 정렬하고 병합합니다.
   - 크기 $n$의 임시 배열(`temp`)을 동적 할당하여 병합 과정에서 사용합니다.
3. **퀵 정렬 (Quick Sort)**
   - 분할 정복 방식을 사용하며, 성능 비교를 위해 세 가지 피벗 선택 방법을 각각 구현했습니다.
     - **First Element:** 항상 구간의 첫 번째 원소를 피벗으로 선택
     - **Random Pivot:** 구간 내에서 무작위 원소를 피벗으로 선택
     - **Median-of-Three:** 구간의 시작, 중간, 끝 원소 중 값의 크기가 중간인 원소를 피벗으로 선택

---

## 3. 측정 항목 및 방법
- **숫자 비교 횟수 (`Comparisons`):**
  - 정렬 과정에서 데이터 값끼리 비교(`>`,`<` 등)한 총 횟수를 전역 카운터(`comparison_count`)를 통해 측정합니다.
  - 힙 정렬은 힙 구성 및 복구 과정의 비교를 모두 포함하며, 퀵 정렬은 피벗 선택 과정의 값 비교도 포함합니다.
- **실행시간 (`Time(ms)`):**
  - C언어의 `clock()` 함수를 사용하여 정렬 알고리즘 함수가 시작된 시점부터 완료된 시점까지의 CPU 시간을 밀리초(ms) 단위로 측정합니다. (데이터 생성, 배열 복사, 출력 시간 제외)
- **메모리 사용량 (`Memory(Bytes)`):**
  - 원본 데이터 배열 공간을 제외하고, 알고리즘 수행 중 추가로 소모되는 최대 메모리를 계산합니다.
  - **병합 정렬:** 동적 할당된 임시 배열 크기(`n * sizeof(int)`) + 재귀 호출 스택 메모리
  - **힙 정렬 및 퀵 정렬:** 재귀 호출 스택의 최대 깊이($\log_2 n$)에 따른 스택 프레임 및 지역 변수 메모리

## 4. 성능 분석 및 고찰

### ① 데이터 크기 증가에 따른 비교 횟수 변화
- 세 알고리즘 모두 평균 시간 복잡도가 $O(n \log n)$이므로, 데이터 크기 $n$이 2배 증가할 때 비교 횟수는 약 2배 이상 증가하며 일정한 증가 추세를 보입니다.
- 병합 정렬은 데이터의 초기 정렬 상태와 무관하게 비교 횟수가 매우 안정적입니다.
- 퀵 정렬의 경우, **Median-of-Three** 피벗 선택 방식이 최악의 분할을 효과적으로 방지하여 전반적으로 가장 적은 비교 횟수를 기록합니다.

### ② 실행시간 차이 분석
- **퀵 정렬**은 메모리 캐시 지역성(Cache Locality)이 우수하고 오버헤드가 적어 일반적으로 가장 빠른 실행시간을 나타냅니다.
- **병합 정렬**은 매 병합 단계마다 임시 배열로 데이터를 복사(`memcpy` 또는 대입 연산)하는 부하로 인해 실행시간이 다소 길어질 수 있습니다.
- **힙 정렬**은 부모-자식 노드 간의 인덱스 연산 및 트리 구조의 비연속적인 메모리 접근 특성으로 인해, 이론적 복잡도가 같더라도 퀵 정렬에 비해 실행시간이 다소 느리게 측정됩니다.

### ③ 메모리 사용량 차이
- **힙 정렬 및 퀵 정렬**은 별도의 대형 임시 저장소가 필요 없고 재귀 호출 스택 공간만 소모하므로 메모리 사용량이 매우 적습니다 ($O(\log n)$ 공간 복잡도).
- 반면 **병합 정렬**은 입력 데이터 크기 $n$에 비례하는 임시 배열을 할당해야 하므로 데이터 크기가 커질수록 메모리 사용량이 급격히 증가합니다 ($O(n)$ 공간 복잡도).

### ④ 퀵 정렬 피벗 선택 방법에 따른 비교
- **First Element:** 정렬된 데이터나 역순 데이터가 입력될 경우 최악의 경우인 $O(n^2)$ 시간 복잡도에 빠질 위험이 큽니다.
- **Random Pivot:** 최악의 입력 패턴을 확률적으로 회피할 수 있어 안정적이지만 난수 생성 함수 호출로 인한 미세한 오버헤드가 존재합니다.
- **Median-of-Three:** 피벗이 한쪽으로 치우치는 현상을 방지하여 편향된 분할을 막고, 퀵 정렬의 성능을 가장 안정적이고 일관되게 유지해 줍니다.

## 5. 시간 및 공간 복잡도 요약

| 알고리즘 | 평균 시간 복잡도 | 최악 시간 복잡도 | 공간 복잡도 |
| :--- | :--- | :--- | :--- |
| **Heap Sort** | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ |
| **Merge Sort** | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ |
| **Quick Sort** | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ |
