# 과제 14: 힙 정렬, 퀵 정렬 및 병합 정렬 성능 비교

## 1. 개요
C언어를 이용해 힙 정렬, 병합 정렬, 그리고 세 가지 피벗 선택 방식을 적용한 퀵 정렬을 각각 구현하고, 데이터 크기에 따른 성능을 비교·분석하는 프로그램입니다.

## 2. 실험 방법
- 데이터 크기(n): 1000, 2000, 4000, 8000, 16000, 20000
- 데이터 생성: 0부터 999999 사이의 무작위 정수(중복 허용)를 생성하여 사용합니다.
- 공정성 유지: 각 크기마다 동일한 원본 데이터를 생성하고, 모든 정렬 알고리즘이 동일한 배열 복사본을 입력으로 받아 수행합니다.
- 정렬 방식: 오름차순 정렬

## 3. 측정 항목
1. 숫자 비교 횟수: 정렬 과정에서 데이터 간의 크기를 비교한 횟수를 카운트합니다. (힙 정렬은 힙 구성 및 복구 과정 포함, 퀵 정렬은 피벗 선택 과정 포함)
2. 실행시간: 알고리즘이 시작된 시점부터 종료될 때까지의 시간을 측정합니다. (데이터 생성, 복사, 출력 시간 제외)
3. 메모리 사용량: 원본 배열을 제외하고 알고리즘 수행에 추가로 소요되는 최대 메모리를 계산합니다.

## 4. 구현 알고리즘 목록
- 힙 정렬 (Heap Sort): 최대 힙을 배열 자체로 구성하여 정렬
- 병합 정렬 (Merge Sort): 분할 정복 방식 및 크기 n의 임시 배열 사용
- 퀵 정렬 (Quick Sort):
  - First Element (첫 번째 원소 선택)
  - Random Pivot (무작위 원소 선택)
  - Median-of-Three (시작, 중간, 끝 원소의 중앙값 선택)

## 5. 결과 분석 및 고찰
- 비교 횟수: 세 알고리즘 모두 O(n log n) 특성을 보여 n이 2배 증가할 때 비교 횟수도 비례하여 증가합니다. 병합 정렬은 입력 데이터 상태와 무관하게 비교 횟수가 일정하며, 퀵 정렬은 중앙값 피벗을 사용할 때 가장 효율적인 비교 횟수를 기록합니다.
- 실행시간: 퀵 정렬이 캐시 지역성과 적은 오버헤드로 인해 가장 빠른 실행시간을 보입니다. 병합 정렬은 임시 배열 복사 과정이 포함되어 부하가 발생하며, 힙 정렬은 트리 구조 특성상 메모리 비연속 접근으로 인해 다소 느리게 측정됩니다.
- 메모리 사용량: 힙 정렬과 퀵 정렬은 재귀 스택 공간만 사용하여 메모리 사용량이 적은 반면, 병합 정렬은 크기 n의 임시 배열을 할당하므로 메모리를 더 많이 소모합니다.
- 퀵 정렬 피벗 방식: 첫 번째 원소 선택 방식은 정렬된 데이터 입력 시 최악의 성능을 낼 위험이 있으며, 무작위와 중앙값 선택 방식은 이를 방지하여 안정적인 성능을 나타냅니다.

## 6. 시간 및 공간 복잡도
| 알고리즘 | 평균 시간 복잡도 | 최악 시간 복잡도 | 공간 복잡도 |
| :--- | :--- | :--- | :--- |
| Heap Sort | O(n log n) | O(n log n) | O(1) |
| Merge Sort | O(n log n) | O(n log n) | O(n) |
| Quick Sort | O(n log n) | O(n^2) | O(log n) |
